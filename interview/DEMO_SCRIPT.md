# Demo script — GTM Enablement Hub (≈3 minutes)

Audience: GTM / SDR leadership at a developer-tools or AI company.

## Why this hub exists

A working system that forces constraint-first discipline: map the value stream, pick the persona, practise discovery and call analysis — with AI as a coach, not a content spitballer. Built for the complexity of selling a multi-module delivery platform.

## Tab map (exact labels)

`Dashboard` · `Solutions` · `SDLC` · `Personas` · `Competitive` · `Discovery` · `Glossary` · `Calls` · `Progress` · `Settings` (About this hub lives under Settings)

## 3-minute path

### 0:00–0:20 — Dashboard
Open **Dashboard**. One sentence: “This is how I organise market → constraint → play.” Point at Solutions / Personas / Battlecards / Discovery counts. Click **Explore SDLC Map**.

### 0:20–1:20 — SDLC (centrepiece)
Walk the **value stream**: Plan → Code → Build → Test → Secure → Release → Operate → Improve.  
Open **Release** or **Test**. Show enterprise problems, persona relevance, Relay module fit, outbound hooks. Optional: **Coach me on Release →**.  
Punchline: Relay can cover the whole stream — but we start where work is waiting.

### 1:20–2:00 — Solutions + Persona
Open **Solutions** → pick the module that sits on the constraint you named.  
Then **Personas** → e.g. VP Engineering — how they think about that pain and what good sounds like. Optional: start roleplay coaching.

### 2:00–2:50 — Discovery or Competitive
**Discovery** → show Q / why / follow-up for that theme.  
Or **Competitive** → **⭐ Top** for a 30s positioning drill.

### 2:50–3:10 — Settings → About this hub
Open **Settings**, expand **About this hub**. State the boundary: Relay is fictional, teaching content is labelled, AI outputs need review.

### Optional (+1 min)
**Calls** → **Load sample transcript** → **Analyse Call**.
